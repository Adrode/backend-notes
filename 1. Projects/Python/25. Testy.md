#test #pytest

## Założenie testów
- Testy robi się po to, żeby sprawdzić czy założenia projektu działają.
	- Tworzę założenie projektu i piszę pod nie funkcje oraz testy.
	- Testy często sprawdzają edge cases.
	- Są przydatne gdy **jedna zmiana w kodzie spowodowała zmianę działania w inny miejscu**.
		- **Wtedy test pokazuje mi że zepsułem wcześniejsze założenie projektu.**
			- Więc poprawiam kod, założenie lub test (zgodnie z tym czego od projektu oczekuję).
## Pytest
- **pytest** - to biblioteka do uruchamiania testów
	- automatycznie znajduje test na zasadzie: najpierw szuka plików `test_*.py` lub `*_test.py`, a w nich funkcji zaczynających się od `test_`
	- testy uruchamia się z poziomu terminala poprzez `pytest test_something.py`
## Asercje
#assert
- **assert** - asercja to sprawdzenie "czy to co dostałem, to to czego się spodziewałem?", czyli czy zwraca `True` (zielony) lub `False` (czerwony)
## Fixtures
#fixture
- **Fixture** - funkcja przygotowująca dane lub zasoby potrzebne do testu. Dla każdego testu fixture zostaje wywołany od nowa (czyli "świeże dane" dla każdego testu)/
	- ```python
	  import pytest
	  
	  @pytest.fixture
	  def przykladowe_dane():
		  return {
			  "name": "Kekw",
			  "age": 18,
			  "height": 170
		  }
		  
	  # wstrzyknięcie fixture poprzez podanie do arugmentu funkcji
	  def test_wzrost_powyzej_150(przykladowe_dane): 
		  assert przykladowe_dane["height"] > 150
		  
	  def test_adult(przykladowe_dane):
		  assert przykladowe_dane["age"] >= 18
	  ```

## Unit tests
#unittest #unit #test 
- **Unit tests** - testy jednostkowe, testują pojedynczy fragment kodu (np. funkcję).
	- Pisze się je tak, jak opisałem powyżej, poprzez pytest, assert, fixture, itd.
## Testy integracyjne
#TestClient
- **TestClient** - specjalny klient, który pozwala wysyłać requesty HTTP do aplikacji, bez uruchamiania serwera
	- Czyli wysyłanie FAKE HTTP
	- Powinny sprawdzać:
		- status code
		- response body
		- edge cases (brak auth, złe dane, brak usera, not uniqe email)
